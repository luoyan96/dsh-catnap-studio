# Catnap 陪伴猫重设计任务书

## 你的角色与工作边界

你是这个任务的 Product Design + 前端实现负责人。主窗口中的 Codex 是总指挥和最终验收人。

工作分为四个阶段，必须按顺序执行：

1. 使用 Product Design 和 GPT Image 基于现有截图生成 **恰好 3 个**明显不同的桌面陪伴方案。
2. 把 3 个方案展示给用户并等待用户选择；选定前不得修改产品代码。
3. 只实现用户选中的方案，完成资源、交互、状态机、音效和测试。

不要构建 EXE、不要发布 Release、不要推送 GitHub、不要改桌面仓库中的 vendored 插件；这些由总指挥在验收通过后处理。

## 当前问题

现在同一只猫以几乎相同的探头姿势同时出现在输入区旁边和窗口右下方，像两个悬浮贴纸。猫的持续上下漂浮、点击后直接打开设置面板、靠近发送按钮和弹出菜单的放置方式都很突兀，缺少“安静陪我工作”的感觉。

本次不是增加更多按钮或数值养成，而是把猫从装饰按钮改成有自然作息的低干扰陪伴角色。

## 核心体验

用户工作时，猫大部分时间安静待在身边，只有隔一段较长时间才自然地换一个动作。用户主动点击工作区猫咪时是在“抚摸它”，不是打开面板。猫会闭眼、轻轻蹭一下，并播放一声短而舒服的本地猫叫或呼噜声。

体验关键词：安静、自然、克制、有生命感、可预期、不遮挡工作。

禁止的感觉：悬浮贴纸、不断弹跳、频繁说话、突然冲入界面、游戏式刷亲密度、自动发出声音、遮住输入框或菜单。

## 两层猫咪必须分工

### 1. 工作区陪伴猫

- 是主要陪伴角色，位于稳定的“桌面/软垫/窗台”落点，不能挂在发送按钮或输入框边缘。
- 可以随主题使用不同猫咪形象和色彩，但同一主题下所有动作必须保持同一只猫的花纹、体型、项圈和绘画风格。
- 允许呼吸、睡觉、醒来伸懒腰、玩毛线球、被抚摸等状态。
- 单击或键盘激活是抚摸；不得再直接打开猫咪伙伴面板。
- 默认不允许像悬浮按钮一样随意拖动。若确实保留拖动，应放到设置中的“自由摆放”选项或改成长按拖动，不能与抚摸点击冲突。

### 2. 底部猫窝入口

- 固定沿用截图中的黑白奶牛猫身份：黑色头背、白色口鼻胸口和爪子、琥珀眼、粉色鼻子、带小铃铛项圈。
- 姿势必须改成缩在自己的柔软猫窝里，不再使用和工作区猫完全相同的探头素材。
- 它是“猫窝中心”的稳定入口和状态提示，不是第二只浮在空中的猫。
- 点击猫窝才打开猫咪伙伴面板；悬停可以眨眼或轻抬耳朵，但不要跳动。
- 猫窝在三个主题中可以换配色，但猫的身份保持一致。

## 陪伴状态机

实现为可测试的显式状态机，不要把随机 `setTimeout` 散落在 DOM 逻辑中。

| 状态 | 触发建议 | 表现 | 声音 |
|---|---|---|---|
| `resting` | 默认，占 70% 以上时间 | 趴卧/坐卧，极轻微呼吸，位移不超过 1–2px | 无 |
| `sleeping` | 一段时间无交互 | 眼睛闭合，尾巴偶尔动一下 | 无 |
| `stretching` | 每 4–8 分钟随机一次，动作间至少间隔 3 分钟 | 起身、前爪下压、背部舒展，约 3–5 秒后回到休息 | 无 |
| `playing-yarn` | 每 8–15 分钟有概率发生，约 8–12 秒 | 毛线球滚入，拨动 2–3 次，再自然停下 | 无 |
| `petted` | 用户点击/Enter/Space，优先级最高 | 闭眼、耳朵放松、头部轻蹭，约 1.5–2.5 秒 | 一声低音量猫叫或短呼噜 |
| `paused` | 页面不可见、外部对话框打开、窗口失焦 | 停止自主动作和计时，保持静止安全姿势 | 无 |

补充规则：

- 首次出现后至少 30–60 秒不执行大动作。
- 用户最近 3 秒正在输入时，推迟伸懒腰和玩毛线球。
- 自主动作绝不播放声音；声音只能由用户直接点击触发。
- 抚摸设置 2 秒冷却，连续点击不能叠加音效和动画。
- 动作结束必须回到稳定休息状态，不能停在半帧。
- `visibilitychange`、窗口失焦和组件清理时必须暂停/清除计时器。

## 抚摸交互

- 指针移动小于 5px 的 `pointerup` 才算抚摸；不要在 `pointerdown` 立即触发。
- 点击猫身体的有效区域要贴合可见轮廓，不能有巨大的透明点击矩形挡住底层 UI。
- 抚摸时眼睛闭合、头部朝触点轻蹭，可出现非常克制的“呼噜…”或小爱心反馈，持续不超过 1.8 秒。
- 使用本地音频资源，不得联网获取；建议 OGG/WebM + MP3 兜底，总时长不超过 1.5 秒，默认音量约 0.15–0.25。
- 在猫咪设置中提供“猫咪声音”开关和音量选项，并持久化。自主动画声音始终关闭。
- 音频播放失败不得影响动画，也不得产生未处理 Promise。
- 可通过键盘聚焦并用 Enter/Space 抚摸；提供明确的 `aria-label`。

## 视觉素材要求

- 必须使用 GPT Image 生成真实透明背景猫咪素材，不能使用 emoji、CSS 图形、占位方框、手写 SVG 或文字代替。
- 现有三套主题的色彩、纸张质感和插画气质必须保留，不重做整个 Harness UI。
- 每种动作使用独立、对齐一致的透明 PNG/WebP 帧或经过验证的动画资源；不要把比例不一致的图片硬拉伸。
- 每个动作的画布尺寸、猫脚落点和视觉重心必须一致，切换时不能跳位。
- 至少需要：休息、睡觉、伸懒腰、玩毛线球、被抚摸闭眼、猫窝入口六组状态。
- 底部猫窝素材单独绘制，不得复用工作区猫的探头姿势。
- 单张资源尽量小于 400KB，整套新增图片和音频尽量控制在 4MB 内。

## 三个设计方向的要求

第一阶段生成恰好 3 张独立的 `1440 × 1024` 桌面应用设计图。每张都必须基于用户截图和现有 Catnap 色彩体系，但应在以下方面形成真正不同的方案：

- 猫咪的稳定落点与工作区关系。
- 猫窝入口的位置、形状与视觉权重。
- 自主动作发生时如何不打断工作。
- 猫与输入区、右侧详情栏、底部状态栏之间的安全距离。

每张只展示一个完整方案，不要把多个方案拼在同一张图里。生成完后只让用户选择 1、2、3，不得在选择前开始编码。

## 布局和遮挡规则

- 不遮挡发送按钮、模型选择器、输入框文字、右侧详情面板、设置、菜单、下拉框、通知和系统弹窗。
- 猫咪所在区域必须有安全边界；窗口缩小时应缩放、换锚点或只保留猫窝入口，而不是覆盖内容。
- 任何外部 `[role="dialog"]`、`[role="menu"]`、`[role="listbox"]` 或重要浮层打开时，工作区猫进入 `paused` 并降到浮层后方或隐藏。
- 底部猫窝入口不得超过状态栏高度太多，不要形成第二个大型悬浮对象。
- `z-index` 必须低于 Harness 交互浮层；不要靠无限增大层级解决问题。

## 动效与性能

- 静止时不要使用现在持续 4 秒上下漂浮的 `catnap-pet-float`。
- 优先使用 `transform` 和 `opacity`；不要在每帧修改 `top/left/width/height`。
- 页面隐藏、窗口失焦或猫被设置为隐藏时，不运行 `requestAnimationFrame` 和自主动作计时。
- 遵循 `prefers-reduced-motion: reduce`：关闭自主动作，只保留静态休息图；用户点击时允许无位移动画的闭眼反馈。
- 低性能设备上应能关闭“猫咪自主活动”。

## 代码改造建议

- 将陪伴逻辑从 `src/client/index.ts` 拆成独立模块，例如：
  - `src/client/companion/state-machine.ts`
  - `src/client/companion/scheduler.ts`
  - `src/client/companion/audio.ts`
  - `src/client/companion/view.ts`
- 把猫咪状态、声音开关、自动活动开关持久化到现有 `dsh-catnap-companion` 数据中，并为旧数据提供兼容默认值。
- 工作区猫和猫窝入口使用不同 DOM 元素、不同资源字段和不同职责，不能继续让 `petImage.src = definition.mascot` 同时驱动所有位置。
- 当前 `petButton` 单击打开 Studio 的行为要改为抚摸；Studio 改由底部猫窝入口打开。
- 保留现有三主题、设置中心、标题栏、状态栏和已修复的对话框防遮挡逻辑。

## 必须新增的测试

- 使用 fake timers 验证状态转换、最短间隔、随机调度范围和清理逻辑。
- 点击工作区猫进入 `petted`，不会打开 Studio。
- 点击底部猫窝才打开猫咪伙伴面板。
- 抚摸冷却期间不会重复播放音效。
- 自主动作从不播放声音。
- 页面隐藏、失焦或对话框/菜单打开时进入 `paused`。
- 用户正在输入时推迟大型动作。
- `prefers-reduced-motion` 下不会自动伸懒腰或玩球。
- 旧版 localStorage 数据可以平滑读取。
- 主题切换后，工作区猫、猫窝入口和设置预览分别使用正确资源。
- 卸载插件时清理所有事件、计时器、音频和 DOM。

## 验收标准

总指挥会按以下标准验收：

1. 连续观察至少 10 分钟，没有频繁或机械重复的动作。
2. 工作区猫 80% 左右时间安静休息，伸懒腰和玩毛线球自然且能完整回到休息状态。
3. 单击猫咪立即产生抚摸反馈，闭眼和轻叫同步，没有打开设置面板。
4. 底部只看到窝在猫窝中的黑白奶牛猫，不再出现上下两个完全相同的探头素材。
5. 模型菜单、设置、首次启动弹窗和输入框都没有被猫挡住。
6. 三套主题、最小窗口、缩放和深色主题均无错位。
7. 无控制台错误、无计时器泄漏、无持续高 CPU。
8. `pnpm run ci` 全部通过。
9. 提供参考截图与实现截图的同尺寸对比，至少覆盖：默认休息、伸懒腰、玩球、抚摸闭眼、猫窝入口、设置/菜单打开六个状态。
